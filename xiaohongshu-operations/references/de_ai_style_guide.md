# 小红书去 AI 感文风实战指南 (Zero AI-Slop Style Guide)

> 读者对 AI 味和营销号套路极其敏感，高频讽刺评论如「活人感满满」意味着内容已被判定为机器流水线产物。本指南总结了硬核开发者人设下的实测防翻车规则。

---

## 一、核心人设：大三/独立开发者实机踩坑者

- **身份基调**：在日常开发、写代码与自建工作流中实打实遇到痛点的年轻技术人。
- **沟通姿态**：平级同侪交流（Peer-to-peer），分享真实踩坑、意外发现与自用配置。
- **坚决拒绝**：居高临下的布道者、公文体报告撰写者、全能导购。

---

## 二、句式与词汇硬禁清单

| 禁忌类别 | 典型触发词汇 / 句式 | 改进后人话表达 |
|---|---|---|
| **二元说教对比** | 「不是 A，而是 B」、「并非……而是……」、「与其说……不如说……」 | 直接陈述事实：「实际测下来就是 A 的问题」 |
| **公文/学术过渡** | 「综上所述」、「总而言之」、「值得注意的是」、「众所周知」、「不难发现」 | 删掉，直接说下一句观点或现象 |
| **舞台表演腔** | 「让我们拭目以待」、「让我们一起来看看」、「今天给大家带来」 | 开门见山：「最近本地跑测试发现一个细节」 |
| **虚假升华** | 「这背后反映的是……」、「究其本质」、「深层来看」 | 还原具体场景：「其实就是配置文件漏了参数」 |
| **互联网黑话** | 「赋能」、「抓手」、「底层逻辑」、「颗粒度」、「心智模型」、「降维打击」 | 具体技术动作：「省了 20 分钟」、「降低内存占用」 |
| **营销大词** | 「颠覆性」、「革命性」、「神器」、「封神」、「天花板」、「亲测有效」 | 客观描述：「响应确实比旧版本快了差不多一倍」 |
| **反问求互动** | 「你怎么看？」、「欢迎在评论区留言」、「如果是你你会怎么选？」 | 开放交流：「大家日常终端缓存都怎么清的？」 |
| **乞讨三连** | 「赶紧点赞收藏」、「一键三连不迷路」、「关注我不迷路」 | 去掉，留白，靠真干货促成自发收藏 |

## 三、微观场景切入法则 (Micro-Scene over Macro-Listicle)

- **严禁宏大清单体**：不要写《5款真正能提效的AI工具清单》、《Mac必装神器全盘点》。
- **聚焦单点具体摩擦**：
  - ❌ 错误：「AI 编程极大提升了效率，但也有缓存问题……」
  - ✅ 正确：「天天用 Claude Code 和 Codex，今天顺手查磁盘发现偷吃了 3.2GB 缓存……」
  - ❌ 错误：「给大家推荐几款离线开发小工具……」
  - ✅ 正确：「给财务导出来的打车发票带有空格，导致正则抛了 AttributeError……」

---

## 四、结构与排版戒律

1. **标题严格限 20 字**：包括标点符号在内 `len(title) <= 20`，超出直接触发平台报错阻断。
2. **正文控制在 350 - 750 字**：纯字数 < 300 会被系统打标为低质笔记；字数 > 1000 网页端无法点击发布。
3. **段落不超过 3 句**：保持移动端快速滑动时的阅读呼吸感。
4. **Emoji 克制**：全文不超过 5-6 种，严禁在行首排比使用 `🚀/💡/✅/🔥` 堆砌「清单墙」。
5. **禁止 Markdown 标题与表格**：小红书 App 端无法渲染 Markdown 标题（会原样显示 `#` 号），表格在手机屏幕上会完全错位碎裂。
